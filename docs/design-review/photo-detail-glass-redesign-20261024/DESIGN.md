## 1. 为什么重做

91 轮的正式稿 [review-editor-v1.png](../photo-detail-export-histogram-20261024/review-editor-v1.png) 对应运行截图被用户否定了两处；这里不把该反馈外推为实体手机验收：

1. 细节页底部那块占画面高度的大黑底工具面板 —— 照片被挤小。
2. 直方图页头「亮度 / RGB / 预览统计 / 暗部 / 高光」连成一整条选中块 —— 读不出哪个是当前项。

随后 `5e9688ba…` 的模式线仍未在 framebuffer 上可见；该失败保留原身份，裁切原因未被证实。旧原生 `f717151b…` 已以实体背景层修复并完成限定验证。本稿把编辑区、细节与从属流程放到同一原型中重新梳理，不将旧原生通过结论当作 v3 视觉通过。

## 2. 三条设计原则

| 原则 | 落地 |
| --- | --- |
| 照片拿走全部可用高度 | 细节页取消底部工具面板，画布用完整安全区；顶部操作覆盖在画布上 |
| 控件退到照片边缘内侧 | 控件是锚定照片 stage 安全区内侧 12dp 的紧凑玻璃浮层，不是通栏面板，照片不因控件开合而位移 |
| 选中态靠结构区分，不靠大色块 | 模式 = 文字 + 2dp 下划线；开关 = 独立 28dp chip；只有真正的单选分段（缩放、比较）才用填充选中 |

## 3. v3部件规格（历史基线，v4更新见第10节）

单位 dp / sp。

### 3.1 共享玻璃材料 `PhotoGlassDrawable`（沿用）

从照片 View 局部 `source.draw()` 采样，采样图最长边 ≤192px，box blur；约 65% 深色 tint + 35% 图色透出，加 1px 细边。照片变换或内容更新时 `refreshGlass()`。采样只作控件材料，**不进入真实像素、直方图输入、草稿或导出数据**。

### 3.2 细节入口（编辑页，照片左下）

- 视觉高 **32dp**，触达高 **48dp**，内容宽约 **91dp**；18dp 放大镜 + 12sp「查看细节」。
- 距照片 stage 左 / 下各 12dp；保留图片比例，不随缩放后的真实图边漂移。
- 改动点：从白底白图标改为深色玻璃；文字前不留空白，整块一起点。

### 3.3 直方图浮层（编辑页，照片上）

- 常规 **280×104dp**，圆角 18，距边 12dp。
- 1.3 字号时外层宽度弹到约 **316dp**，上限 **328dp**，并受实际可用宽度约束 —— 避免警示百分比截断。
- **位置**：照片上方有足够留白时优先占留白（避开人物主体）；留白不足才锚到照片上缘右侧。横屏改走右上。
- 行结构：`亮度 | RGB | ——弹性—— | [暗部] [高光]`，行高 28dp，触达 48dp。
- 模式：文字 + 文字下方 2dp 短下划线，与独立警示 chip 区分。HTML 用 CSS 表达；原生必须真实可见，不能以代码存在代替截图证明。旧 f717 使用实体背景层，不把旧 onDraw／clip 假说沿用为新结论。
- 警示：两个独立 28dp chip，中间 6dp 间隔。高光暖色斜纹、暗部蓝色斜纹，**图案 + 文字双重编码**，不只靠颜色。
- 图表：256 bins、x 轴固定 0–255、纵轴按该快照最大计数归一化、RGB 三线共用纵轴。角标常驻「预览统计 · 8 位 sRGB」。

### 3.4 细节页浮层

| 浮层 | 位置 | 规格 |
| --- | --- | --- |
| 顶部 header | 覆盖画布，渐变底 | 52dp 高，返回 48dp 触达，标题两行（状态 + 文件名） |
| 比较胶囊 | 顶部居中，header 下 | **216dp × 40dp**，两段「当前效果 / 调色前」 |
| 尺寸 / 倍率 tag | 照片右上 | 独立玻璃 tag，26dp 高，**11sp 单行**，避开 header 与胶囊 |
| 缩放浮层 | 照片左下 | **232×55dp**（1.3 字号 → 268dp），仅「适应 / 100% / 200%」，选中视觉 32dp、触达 48dp |
| 定位小窗 | 照片右下 | 76×98dp，底部抬至 76dp 以避让缩放浮层；仅放大时出现 |
| 说明行 | 底部操作上方 | 10.5sp 两行，渐变底，不拦截触摸；放大时给右侧定位窗留位 |

改动点：**尺寸 / 倍率从左下控件里拆出来**，不再和缩放按钮共占一块面板。

### 3.5 状态分支

| 情况 | 标题 | 说明行 | 调色前 |
| --- | --- | --- | --- |
| 可恢复当前编辑 | 细节预览 | 同构图对比 · 不含边框 | 可用 |
| 缺可信参数 / 关联的历史 JPEG | 已保存版本 | 查看完整文件像素 · 含已烘焙边框 | 禁用，说明「此版本暂无法恢复调色前内容」 |

禁用态保留文字原因而非只变灰，可被辅助功能读出；**不出现「不含边框」承诺，也不推测剥框**。

### 3.6 编辑区与完整交互

竖屏使用两行 chrome、剩余照片 stage 和同高工具区：176dp panel＋48dp 五入口行，随原型字号系数扩展。切组共用编辑状态，不因切组重置照片；横屏照片在左，300dp 右轨包含头部、五组 panel 和入口，内部滚动。

| 分组 / 从属流程 | 可操作内容与边界 |
| --- | --- |
| 滤镜 | 在线／我的、分类、横条与完整三列选择共享来源／搜索／分类；计数从示例列表真实筛选结果计算，失败样例可重试、不支持项禁选；不是生产目录数据或真实 NCP 渲染 |

## 6. 审核时想确认的点

1. 直方图默认落在照片上方留白是否符合预期；留白不足时锚到上缘右侧是否可接受。
2. 尺寸 / 倍率独立成右上 tag，是否比原来挤在左下更好读。
3. 模式用下划线、开关用 chip 的区分强度够不够 —— 这是上一轮反复没解决的点，想在稿子上先定死。
4. 细节页取消底部面板后，操作是否还够明确（适应 / 100% / 200% 只剩左下一处）。
5. 五组工具、完整滤镜、构图取消／应用与配方是否能顺畅完成一轮编辑。
6. 导出设置、已有／未知回执、原始文件与停止／重试的文字是否清楚；窄屏、横屏和大字下是否仍易读。

## 7. 边界

原型中的照片、文件名、参数、直方图形状与百分比均为示意绘制，**不是实测值**，也不是 App 已实现截图。玻璃效果在原型里用 `backdrop-filter` 近似，与原生 `PhotoGlassDrawable` 的采样模糊不是同一实现。原型 CSS 缩放不能证明物理像素1:1、真实处理画质或裁切输出。
