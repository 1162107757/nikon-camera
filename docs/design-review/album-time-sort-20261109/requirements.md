# 相册时间排序 · 审核提案

用户要求：相册界面需要按时间排序，先设计排序。当前为设计，未实施到 App。使用现有纸白／炭黑和用户刚选的 B 版毛玻璃短浮层，照片、来源条及导航保留原结构。

## 入口与面板

用户最新确认：入口沿用预设筛选的小图标形式，图形换成上下双箭头。在现有“共 x 张／选择”这一行右侧、“选择”左边增加约 20dp 的炭黑上下箭头线图标，48dp 隐形触摸区域；移除中间“拍摄 ↓”胶囊，不新增常驻横排。点击展开内容高度约 235–255dp 的自定义底部悬浮面板，临时覆盖导航。顶部标题“时间排序”及小关闭图标；两组分离胶囊：

| 选项组 | 选项 | 建议默认 |
| --- | --- | --- |
| 排序依据 | 拍摄时间／添加时间 | 拍摄时间 |
| 排列顺序 | 新到旧／旧到新 | 新到旧 |

选中项炭黑底、白字及小勾，未选中项淡色半透明，按钮间距至少 8dp。文字以 12–14sp 为主，标题约 16sp，保留 48dp 触摸范围。底部为轻量重置文字和小型应用按钮，不使用系统单选弹窗或整屏说明。小屏／大字时面板内容可滚动，确认始终可达。

入口只显示上下双箭头，不附带“排序”或“拍摄”文字；无障碍名称为“排序”，完整描述注明当前时间依据与顺序，长按可提示“排序”。当前选中条件在展开面板中表达，不添加角标或额外状态横排。多选期间隐藏或禁用排序，避免已选照片移位；不改变 181 正在实现的顶部取消／已选数量／全选及底部三个操作。

## 交互与时间语义

1. 打开时复制当前条件；应用才保存并重排，关闭／返回丢弃未应用修改。重置把面板草稿恢复为拍摄时间、新到旧，仍需应用。
2. 应用相册、手机相册各记住自己的排序，返回 App 及切换来源可恢复。切换排序前后尽量保持当前可见照片为滚动锚点；时间依据变化引起分组变化时以该照片定位，不强制跳页顶。
3. 拍摄时间优先可信拍摄元数据；缺失／无效时回退到添加时间，不向用户伪造拍摄日期。添加时间分别指应用接收／导入时间、系统媒体库的入库时间。时间同值用稳定的照片 ID 排序，避免刷新后抖动。
4. 日期分组必须跟随当前时间依据及方向。例如按添加时间时，日期标题也按添加时间形成，不能混用。跨年展示完整年份；今天／昨天或月日沿用既有日期表达。
5. 同一原图及它的所有编辑版本仍为一组，以原图的时间排序，不因切换版本／生成编辑图而跳到最新日期；重复别名不重复计数。RAW／JPEG 使用一致排序，照片格式标记保留。
6. 手机相册必须在系统查询／全数据边界内按选中时间及方向分页，不能只对已加载一页排序。不可一张张在 UI 主线程解码取 EXIF；查询现成日期元数据、后台索引并缓存，权限变化／删除／新增后按真实状态更新。

## 代码核对与待实施点

当前 LocalPhotoRepository 的手机媒体库查询是 DATE_ADDED DESC、ID DESC，PhonePhoto／describe 也以添加日期为主要数据；这与新提案的拍摄时间默认并不相同。实施时需要补齐正确时间字段、回退和全库分页，不是仅增加视觉按钮。应用相册分组时间也需统一元数据来源，不能直接把渲染工作文件 lastModified 当拍摄时间。
