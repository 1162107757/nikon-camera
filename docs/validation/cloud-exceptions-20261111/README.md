## 修复

APK 签名前原先会收集整个对象的所有分块，再 `Buffer.concat` 为完整 APK。并发读取和完整副本会增加峰值内存。这是代码中可复现的内存风险；旧平台日志缺少业务路由，因此不将历史 3 个请求的具体接口作无依据断言。

1. COS 下载前改为流式校验完整 SHA-256 和精确长度，逐块处理，不保留整包或全部分块。
2. 同一对象、同一长度的在途校验合并为一次读取。完成结果不缓存；后续请求仍重新校验。异常／校验失败均清理在途状态，允许后续重试。
3. 每个请求仍使用自己的请求级凭据生成签名，并复查撤回状态。保留长度、路径、哈希、签名有效期、下载限流和条件请求规则。
4. 已关闭的下载连接跳过后续读取／签名处理；其中一个请求断开不会取消其他仍在等待的有效下载。
5. 添加固定接口分类、追踪 ID 的受限上下文日志，取消为信息日志，真正 5xx 单独标记。新增日志不记录完整 URL、参数、请求头、正文或凭据，便于后续按平台请求 ID 定位接口。
