# 94 · 实施与证据

## 变更

- 编辑页立即打开细节弹窗，取消在编辑IO队列中重复计算整文件SHA；细节Source仍在展示任何像素前后台校验源文件。
- Source先解码最长边不超过1024px的真实预览，按冻结的调色、构图和方向处理，再补完整细节。预览明确标记为provisional，不会完成真实100%/200%的认证。
- 已保存JPEG、中性当前图及中性调色前图在方向为1、构图无变化时直接读取JPEG区域；有编辑、构图或方向变换时保留完整无损处理。页面内复用校验结果、预览和有界tile缓存；不引入跨账户缓存。
- 直接JPEG分块多读取一圈相邻像素，再按整数位置裁回原范围，避免JPEG色度重建把分块边界当成照片边缘。原图由只读解码器持有，关闭只删除自有临时PNG。
- 载入词收为“载入中…”和“细化中…”，文字按内容宽度布局并限制最大宽度。右上尺寸未知时隐藏；真实尺寸就绪后显示尺寸，完整帧完成后才显示缩放百分比。
- 运行时“照片直播”及相关旧称统一为“边拍边传”。现有项目、文件路径、协议与数据标识不改。

## 证据入口

最终APK与207项生产输入由[FINAL-IDENTITY.json](FINAL-IDENTITY.json)固定。性能报告按候选SHA／唯一运行ID分目录，原生界面报告按phone与font1.3分目录。

初始候选5329d895的UI像素守卫失败：高频JPEG的tile比对88点不同，framebuffer43点误差超过2，最大差48。原报告、图片和阈值完整保存在[失败归档](initial-5329d895-jpeg-boundary-fail/UI-MATRIX.json)，不计为最终通过。邻域读取修正后的54e0022f又暴露2401×1601采样2末边向下取整造成裁剪越界，像素守卫未到达，详[第二次失败](second-54e0022f-odd-sample-edge-fail/UI-MATRIX.json)。最终35426c20按实际解码范围裁切，少于一个采样单位的末条单独sample1解码；两次失败均保留，最终仍使用原零误差判据。

性能旧基准复现旧JPEG→整图渲染PNG→预览及区域解码流程，不是旧APK对照；“冷”仅指新Source，未清OS磁盘缓存。每项为单次模拟器观测，不承诺实体手机耗时。已调色完整处理不保证更快，优化重点是先显示照片和跳过未编辑图的重复转换。

最终[性能报告](35426c20/e5d0ba6c14dc43b6a270d29bf05f5b46/report.json)为121次断言执行PASS。自有4000×3000 JPEG、6,237,926字节；完整可视帧与首预览分开计时：

| --- | ---: | ---: | ---: |
| 已保存JPEG | 67ms | 1.592s | 0.478s |
| 未调色当前图 | 66ms | 1.685s | 0.483s |
| 已调色图片 | 194ms | 3.879s | 4.350s |

普通JPEG完整帧约减少70%；已调色完整处理本次约慢12%，但预览先到，不再全程黑屏。100%／200%真实region使用sample=1；2,184个12MP JPEG及1,716个奇数尺寸JPEG原像素采样均0差。2401×1601的适应采样2、2049×1025单像素末边可成功完成，不将其表述为采样2逐点像素一致。8次Source关闭均确认worker结束与UUID暂存目录不存在，原图SHA保持，自有性能夹具删除。
