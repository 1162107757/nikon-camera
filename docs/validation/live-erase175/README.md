# 175 · 实时无高亮修补

用户要求手指滑动时直接显示实际修补结果，去掉高亮，并改善硬边和周边色差。仅默认修补工作区及新建修补算法采用新规则，其他局部／人像／手动选区的显示规则保持各自范围。

## 行为与融合

- DOWN／MOVE 后台更新实际 renderer 画面；单个工作线程只保留一个最新待处理请求，避免每次 MOVE 入队。UP 用同一笔轨迹精确渲染后才写入暂存模型、增加一次内部撤销。完成只提交一次父事务。
- 默认画布只画实际照片；不绘制正在涂抹或已完成高亮，也没有选区眼睛按钮。取消、失焦、第二指及过期异步回调丢弃本笔预览，不污染历史。导引分配 OOM／最终渲染失败保留原状态并恢复操作。
- 笔刷半径内为完整替换核心，柔边向外延伸，避免只提高向内羽化而残留暗圈。颜色／亮度匹配从选区外的干净上下文估计，使用有界稳健线性光平面；归一化来源采用预乘 alpha 的线性光双线性取样。
- 每项新修补显式记录 contextBlend；仅含旧项的配方仍写 v7、旧渲染逐像素不变，新项写 v8，可读取 v1–v8。缓存身份包含新模式，混合旧新修补可重开。更多中的手动来源仍可用。

## 验证

[摘要](summary.json)和[源指纹](source-inputs.json)绑定 full SHA `a9eb73310d8ae98ef06530469c2576dab65c2a4f7187cf740b47f0f15ccba437`；四组实际安装的都是最终签名交付 SHA `0760e95f2b6370d59a07a8e691d58c8ac3fbd6f01e4218e157abe67aa6f4d3f0`。

[实际截图索引](capture-index.json)为 phone、840×1890/font1.3、横屏、1600×2560 平板，共 4×157 条含重复断言／28 张原始 PNG。实际 DOWN 保持未抬起时等待真实修补帧；整画布逐像素与当前 renderer 帧比较，验证没有叠加高亮。100 次 MOVE 只触发 3 次渲染且并发为1；每笔一次内部撤销。取消、失焦、双指、迟到结果、导引 OOM、精确渲染失败、手动入口、父事务、真实 v8 草稿重开及源文件字节均检查。phone 首帧184ms仅为本次模拟器合成夹具观测，不是实体机性能承诺。横屏设置 system night=yes，照片采样材料不因此独立认证整个 App 的 dark theme。

[host 日志](host-final.log)分别记录 local 43,230、旧修补153,740、自动匹配46,702、新融合973,393条含逐像素断言。新融合覆盖已知干净背景／色偏供体、EXIF1–8、透明供体与目标、范围外零改变、线性光双线性取样、取消清理、v1/v7/v8格式与缓存身份、64MiB堆下24MP小修补有界写入。[合成对比](quality/comparison.png)仅演示可控背景：核心MAE由21.425降至0.449，共同边缘环由3.997降至0.394；不是任意真实照片质量统计。

初始私有 native harness 在构造不可变 Bitmap 的 Canvas 时失败，未进入产品操作；已改可变夹具后重跑四组通过，失败报告保留，不伪装产品缺陷。作者实际打开28图接触表并复核 phone、font1.3、横屏大图；当前范围无新增遮挡、错位或高亮，未扩展为全应用视觉认证。
