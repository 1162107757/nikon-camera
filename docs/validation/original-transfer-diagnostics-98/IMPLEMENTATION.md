# 98 原图传输诊断与重复接收修复

用户附件原始文件 13,672,454 字节（13.67 MB / 13.04 MiB），主图 6048×4024，主图可以完整解码。仅从临时附件读取元信息与校验，不把用户照片加入项目、测试资源或安装包。用户最新反馈这张图最快约 37 秒，慢时超过一分钟；整段平均约 0.37 MB/s，超过一分钟时低于 0.23 MB/s。该值来自用户估时，不是对无线链路的测量。97 的排队耗时改进不能当作解决该吞吐问题。

## 重复接收修复

回归发现，原图传输前后描述符发生变化时，原候选会保留失败，但旧 LiveChanged 处理又把相同 handle 放回 inspect，后续观察到的新描述符被当作新候选，再发一次 GetObject。原失败检查在 98 中持续失败，诊断输出显示 race=true、completed=1、photos=2：原错误项仍存在，同内容变化项却又下载并保存。

98 让 LiveChanged 携带刚观察到的身份，错误时仅将该身份基线记录到 known，清除该 handle 的重复检查。旧失败回执保留；同一已观察描述符和重复事件不再触发另一次自动原图接收；后续真正不同身份仍由正常发现流程接收。校验不通过的原图仍不提交。新增回归覆盖重复事件、没有二次下载、之后新身份仍能正常接收。未证明用户本次 37 秒正是此分支造成，不承诺实机提速幅度。

## 分段记录

保留原有单线程 PTP 会话、256 KiB 分块、15 秒单次读取超时、90 秒无进展预算与 10 分钟总预算。不加入自动 GetObject 重试，不采用之前无稳定收益的 SO_TIMEOUT 缓存试改。

仅对流式 0x1009 原图接收追加固定事件 PTP_ORIGINAL_PROGRESS / COMPLETE / FAILED；约每两秒完成分块后记录一次，并在底层读取超时时留记录。字段全为数字：连接与事务编号、已接收 payload 字节、声明总量、总耗时、payload 读取累计耗时、目标流 write 累计耗时、进度回调累计耗时、读取超时次数。处理带 bytesTransferred 的超时后继续原帧，按真实读到的 payload 计数。包头、最初数据响应、末尾完成响应和其余调度时间不计入 payload_read_ms，所以不能把字段简单相加当作纯无线时间。

ORIGINAL_PRIVATE_SAVE_BEGIN / COMPLETE 标记缓冲 flush、fsync、JPEG 校验、后置 ObjectInfo 核对及私有原图提交这段路径；它包含后置相机信息核对，并非纯磁盘时间。该核对的 0x1008 原有操作耗时也独立记录。系统相册发布独立运行，未改动。

新日志字段不记录照片内容、文件名、对象 handle、SSID、相机序列号或异常消息。沿用固定 schema、256 条上限、64 KiB 上限及十秒后台批量写入；同时按字节裁剪内存和磁盘内容。历史单行上限扩至 512，避免长数字记录在重启后被旧 240 字符门槛丢弃；边界测试覆盖长行恢复及大字段批量裁剪。未配置追踪时不分配分段计时对象。新增日志不逐块 fsync。

## 现有报告导出

设置 → 使用帮助 → 导出最近报告。无需先生成预设导入报告；当前连接记录会加入 JSON 的 connectionTrace。已有 JSON 报告字段和原 appVersion 保留，新增 reportExportAppVersion 表示导出程序版本；旧非 JSON 文本保留为 originalReport。仍由用户选择文件保存位置，不上传或发送任何报告。

建议用户更新后只重测这张照片，传输结束或失败后立即导出并返回 JSON，以区分持续低吞吐、长等待、重复读取和保存阶段耗时。诊断是下一步实机取证，不是已定位无线根因。

最终 PTP/IP、trace 边界、相册控制器和项目回归输出分别记录在本目录。新测试验证两类短超时、精确字节计数、无敏感消息、完整/失败区分及重启保留；完整相册回归包含之前失败项和新重复接收检查。
