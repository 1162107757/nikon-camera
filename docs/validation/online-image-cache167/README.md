# 在线资源缓存 · 167 / 0.30.13-beta

## 实际流量来源与改动

预设主列表使用安装包内的 10 张摄影样片，在手机上应用配方生成模拟效果；这些底图不从 COS 反复下载。生成模拟图需要的 NCP／NP3 原始配方已有独立磁盘缓存（8 MiB／256 份），详情里的“实拍参考图”也已有 URL 对应的本地副本。本次补齐重复请求合并与浏览参考图的容量控制。

- 新浏览参考图保存在 `files/online-presets/image-cache`，最多 100 MiB／256 张，按最近访问时间清理。读取返回独立字节数组，避免清理文件与解码同时进行时出错。
- 同一缓存目录、同一参考图 URL 的并发读取共用一个传输及其结果，跨 Activity／repository 实例生效。失败不缓存；下次可以重试。缓存写入失败仍可显示本次下载结果。
- 缓存先验证图片完整性、格式与解码，损坏后重新下载，保留每张 8 MiB 的网络上限。生产沿用 `PreviewImages` 验证器。
- 已存在的 `previews` 副本继续离线复用；明确下载预设时配套样片仍保存并关联到本地记录。该目录可能包含用户已保存的内容，不参与自动淘汰，也没有批量迁移或删除历史文件。因此 100 MiB 限制仅指新浏览缓存，不是全部预设数据的总大小。
- 参考图以完整 URL 的 SHA-256 为键。内置服务的内容哈希文件名换图后 URL 会变化，从而获取新图。没有给自定义服务的同 URL 内容增加 HTTP 条件重验证；其沿用原有 URL 缓存语义。
- 配方请求锁改为进程内共享，显式下载也经由已有预览配方缓存，避免列表预览与详情下载同时传输同一配方。校验与“浏览不加入我的预设”的行为保留。

目录刷新和社区接口仍联网获取数据；没有修改服务器、COS、CDN 或官网策略。首次访问、资源 URL 改变、缓存被淘汰或损坏时仍会产生下载流量。未执行公开发布。
