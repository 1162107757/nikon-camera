# 局部蒙版与取样修复模块

本记录仅覆盖三个新增生产文件及其主机测试。主编辑器、草稿、渲染器和最终 APK 接入由根任务完成，不能将本模块测试称为完整功能已验收。

## 已实现

- 不可变 `PhotoLocalEdits`：画笔、径向、线性渐变蒙版，曝光（0.1EV）、色温、饱和度，羽化、反选、启停、增删；最多 16 个蒙版，每笔最多 512 个轨迹点。
- 明确取样点与目标点的羽化克隆修复；最多 64 处。它复制取样内容，不生成或猜测图像内容。
- 图像坐标保存为 EXIF 归一后的完整照片坐标，位于用户裁剪／透视／边框之前。共享 `Pixels.exifOrientation()` 为主预览提供默认 1，为 raw 方向的完整导出／细节提供实际 EXIF；默认 local profile 自动读取该上下文，显式 EXIF 构造仅用于明确覆盖。
- 全局调色后依次应用局部线性光颜色混合，再依次执行克隆。透明目标像素不变，目标 alpha 保留。零参数／全部停用时返回原 profile，保持旧渲染路径和模型身份。
- 处理使用单行 ARGB 缓冲。画笔有固定 16×16 空间索引；克隆在写入前保存一个源区域快照，避免重叠区域逐行污染后续取样，源块超过 8,388,608 像素（32MiB）时明确拒绝，照片原始尺寸不降级。
- 新增独立局部工作区，照片默认按完整比例 FIT 显示，双指缩放／移动（1–8倍）、“适应”恢复视口；指点以完整图像逆映射保存。第二根手指加入时撤回尚未完成的单指笔画，双指导航不会误加蒙版。提供选中列表、三类工具、新建、启停、反选、删除、区域叠色、参数与区域页、取样修复、32 步临时撤销／重做。点击“应用”只回调一次，取消／Back 不回调，不自行写草稿。

## 集成契约

`PhotoLocalEditDialog(Activity, Bitmap initial, PhotoLocalEdits, Renderer, Consumer<PhotoLocalEdits>)` 的 initial 和 Renderer 输出都必须是 EXIF 归一、尚未用户构图的照片。传已经裁剪的图片会破坏归一坐标，不应这样接入。

initial 为借用位图，Dialog 不回收，调用方须保留到 dismiss 并负责其所有权。Renderer 每次返回一张独立、归 Dialog 所有的位图，Dialog 在替换或关闭时回收。Dialog dismiss 关闭 LatestPreviewQueue、停止单工作线程并释放持有的渲染图；过期任务结果交队列丢弃回收。上层仍须通过原有账号／照片代次保护 Renderer，关闭后清除对 Dialog 的持有。

`LocalEditsPreviewProfile.of(base, edits)` 放在全局调色后、Geometry／Border 包装之内。`PhotoLocalEdits.write/read` 自带版本 1 和严格数量／有限数／尺寸边界；上层需要新的 Draft 格式、完整相等性、历史、导出冻结、缓存身份与所有 Draft 重建入口保留该模型。

## 已完成验证

`tests/run-photo-local-edits.ps1` 在 64MiB Java heap 下通过 43,230 项检查：不可变模型、序列化与越界拒绝、三类覆盖范围、局部色彩及 alpha、EXIF 1–8 raw／定向输出逐像素一致、克隆重叠源快照、边界取样及 EXIF 镜像半像素取样一致性、取消前零 I/O、源块上限先于分配拒绝、24MP 逐行内存及单调进度。结果及受测源摘要见 HOST-RESULT.json。

三个新增生产文件已在 Android API35 下独立 javac 编译通过；尚未执行最终 APK 的原生手势、取消／应用、历史、草稿恢复和截图检查。根任务进行统一构建与原生验证，不运行本模块单独 ADB 或线上发布。
