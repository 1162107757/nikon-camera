## 已实现

### 机内预设

入口：相机详情 → 机内预设 → 选择已有内容的 C1–C9 → 确认删除。空槽不删除，内置 Standard 不出现在可删除目标中；应用内预设不删除。

读取并显示相机声明的能力。缺少 `0x90CE` 时不发删除请求，提示到相机菜单处理。删除使用专用 `DelCstPicCtrl(item)`，单参数、无上传 data，绝不使用 `DeleteObject`、清空存储、设备重置或空数据写入替代。

确认绑定目标编号、名称和原始字节／SHA。后台重新读取设备、能力、九槽，再复查目标；若相机声明照片／视频当前预设属性，读取 `D200 / D237`，拒绝删除正在使用的槽位。确认期间变化、相机身份不一致、当前照片任务或上次导入尚待核对时停止。写前保存私有 `slot-deletions/<uuid>/before.dat` 和 `intent.json`，完成／失败后保存 `result.json`，当前诊断报告可导出。

一次 owner 只尝试一次删除。ACK 后读取九槽：目标为空且其他八槽原字节不变才显示成功。拒绝、超时、错事务、损坏或不一致读回均不自动重试或恢复。USB 使用独立删除模式并释放自有连接；无线成功后由原 socket 的确认与空槽读回证明移交只读 owner，保留连接。协议状态不明时关闭连接，要求重新读取核对。

主资料：[libgphoto2 的 Nikon 操作定义](https://github.com/gphoto/libgphoto2/blob/master/camlibs/ptp2/ptp.h#L595)列出 `0x90CE` 和单参数／无 data；[Nikon Z6II 管理优化校准说明](https://onlinemanual.nikonimglib.com/z7II_z6II/en/09_menu_guide_03_13.html)说明相机菜单中的删除能力。这些资料不证明具体机型固件的远程删除已经实测。

### RAW 图片

- 手机相册查询与导入接受 NEF／NRW、DNG、CR2／CR3、ARW、RAF、RW2、ORF、PEF、SRW 和通用 RAW 的 MIME／扩展名；实际解码仍由随包 LibRaw 判定，不因扩展名就接受损坏文件。
- 点按手机 RAW 直接准备完整像素的编辑底图，随后使用既有 JPEG 编辑器；无需先手工走完显影界面。批量入口使用同一准备过程。
- 相机 RAW 文件菜单增加“编辑照片”：未下载时先完整下载并校验，已下载时直接准备，自动回到同一编辑器。原有可手动调白平衡、曝光和色彩模式的 RAW 显影入口保留。
- 原 RAW 保留原始字节；私有显影缓存按源／设置身份区分。工作 JPEG 为完整尺寸、Q100、8-bit sRGB，复用前核对身份和哈希。曝光、焦距、光圈、ISO、拍摄时间等可读取的 EXIF 随底图保留，供既有边框与照片信息使用；方向归一化，不复制 GPS。滤镜、基础／局部调节、曲线、HSL、调色盘、去灰、人像、构图、边框及导出沿用原编辑链路。
- 原生缩略图／嵌入预览用于列表，不为列表缩略图触发全尺寸 RAW 显影；缺预览时可点击继续处理。
- 相册与同步缩略图左下角为 10sp 格式标记；编辑页在原有副标题行显示“NEF · 编辑照片”等，不新增一行、不放大按钮。旧显影副本可识别为 RAW，PNG 底图可识别其来源。导出后的实际 JPEG 文件显示 JPEG。
