# 101 / 0.21.2-beta：紧凑传输状态

用户要求开始实施传输分析、速度和剩余时间显示，并将能简短的提示尽量缩短、减少占用空间。本版基于已发布100，本地构建，不修改线上更新策略。

## 最终行为

- 边拍边传进度由76dp两行缩为48dp单行；手动下载保留一行速度、剩余时间、百分比与停止按钮。文件名、大小、平均速度、耗时、排队和错误说明点击详情查看。
- 边拍边传、手动JPEG下载和遥控拍后传入共用字节／单调时钟估算。最近约5秒采样平滑速度；初期不足1秒不显示不稳定速度，未知总量不显示剩余时间；连续5秒未收到新字节显示“等待相机”，新数据恢复后自动更新。接收满额先显示“保存中”，持久保存成功仍由原有回调确认。
- 状态刷新每秒一次，不发送额外相机命令。原图缓存复用仍保留，命中缓存不产生虚假高速测速结果。停止仍完成当前原图后停止剩余下载。
- 遥控页以短词显示状态，点击展开说明；保留拍摄结果未知时的核对路径，绝不自动重发快门。根据实际观察的Wi-Fi路由状态区分Wi-Fi断开／会话断开；没有已观察的原因时仅显示“连接已断开”。取景暂停单独显示，导入中不提供取景恢复按钮。
- 新增离线报告分析脚本 `scripts/analyze-original-transfers.mjs`。只输出固定数字统计，不回显照片名、相机身份和报告其余字段；完整、失败、截断记录分开，未完成记录不计入完成测速中位数。

## 接收分析及限制

已用新分析脚本核对用户此前提供的报告：一张12,853,156字节原图接收111,032ms，payload读取110,465ms（99.5%），写盘77ms，进度回调78ms，其他阶段412ms；平均0.116 MB/s，无底层读超时。该报告保留49条原图数值样本，最长采样间隔2,884ms；采样间隔不能当作网络停顿。

因此没有盲目调整缓冲、并发PTP请求、重连或厂商休眠命令。本版改善状态与诊断，**不宣称相机原图吞吐已提高**。仍需实体相机在相同距离、同一原图条件下多次复测。未连接或操作实体手机／相机，未发布101。
