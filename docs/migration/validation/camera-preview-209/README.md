# 209：相机 RAW 缩略图与筛选衔接

本轮针对 Z 6_2 通过 Wi-Fi 连接后，JPEG 页显示零张、切换 RAW 后仅有文件名的问题。原工程和既有冻结记录保留，整体迁移仍在进行。

## 修复范围

相机已经能够枚举 NEF，JPEG 页为空是格式筛选的结果；此前页面没有读取相机缩略图的调用，也没有把连接页的 RAW 选择带回首页。本轮接入 `camera.thumbnail`，在连接页与同步首页显示相机生成的 JPEG 预览，并共用同一应用会话内的 JPEG / RAW 选择。首页增加相同的格式切换、刷新和错误重试，空列表明确提示另一种格式，数量改为当前格式的“已读取”数量。

缩略图沿用原相机实现的 Nikon GetLargeThumb，遇到不支持或该照片缺少大预览时回退 GetThumb。不会为生成缩略图调用 GetObject 下载 NEF，也不解析或重写 RAW 像素。文件名、尺寸和原片接收保持独立。只有当前相机会话已列出的对象才能请求预览；写入缓存前再次核对对象元数据，拒绝已变化的原文件。

可见行的缩略图依次读取、重复请求复用结果，滑动或离开页面不会取消正在传输的 PTP 操作。旧会话的迟到回复被丢弃。单个预览上限 8MiB，磁盘缓存最多 64 个文件、合计 32MiB，界面解码限制在 256×256 内。失败的预览可单独点击重试，不会自动反复请求相机。刷新会重新枚举存储卡目录，避免一直复用旧索引。

## Apple 验证

最终 [Actions 43204328202](https://github.com/1162107757/nikon-camera/actions/runs/43204328202) 成功，job `131135538372`、artifact `13940465435`。下载后独立核对 IPA 的 iPhoneOS / ARM64、最低 iOS 16、build 209、未签名状态、源码及完整共享黄金结果。170 项 Flutter、565 项共享核心、38 项原生头像检查，以及 1 个真实 PhotoKit / 图像 / RAW / 导出综合场景通过。

`dist/migration209/` 保留 Android arm64 手机包、x64 模拟器包和未签名 iPhoneOS ARM64 IPA。Android 包核对 build 209、最低 Android 8、签名、R8 JNI 保留、字体 / 模型和 ELF / ZIP 16KiB 对齐。IPA 需自行签名安装。
