# 208：JPEG 原始文件直接保存

交付源码为 `1e5acb6c57e63f9a586235109f19b2f66336fdc1`。原工程及 204–207 冻结记录保留；整体迁移仍未完成，范围见[功能清单](../../feature-parity.md)。本轮接续 207，将 JPEG 原始文件从系统分享入口改为 Android / iOS 原生相册保存。

## 行为与边界

原始文件独立于当前编辑配方、边框、成品尺寸、质量和导出版本。源身份、账号、SHA-256 与大小通过共享核心校验，再复制到按账号和操作隔离的快照。复制采用有界缓冲、取消检查与落盘同步，保存前后核对文件身份。每个账号最多保留 8 个未确认快照、合计 1GiB；不会为腾出额度删除尚未确认的保存任务。

用户确认后生成一个保存操作标识；失败重试沿用原标识，明确重新保存才创建新副本。账号变化会取消原任务、清除窗口中的旧文件和收据，并丢弃迟到的回复。相册确认完成后只释放对应快照，保留用于重试的绑定与保存记录；结果不明确时保留快照。原图、应用内成品及编辑草稿保持原样。

Android 使用独立的精确文件发布路径，避免旧原图日志按内容摘要合并两次明确保存操作。Android 10 以上添加照片不要求读取权限。iOS 使用 PhotoKit 原文件资源添加，不调用 JPEG 日期重写路径。两端均在可读时核对已保存资源的实际字节。

原始 JPEG 保留原文件全部内容，包括已有 EXIF、方向和可能存在的定位；确认窗口沿用原版说明。PNG 和 RAW 目前仍通过身份检查后打开系统分享入口；RAW 的独立格式、目标选择、源文件配对及远程下载流程不计作本轮完成。
