# 211：自动边拍边传（A1）

接通清单第 1 项：Nikon 相机在应用前台自动发现、接收新 JPEG，加入拍摄项目，并按可选默认预设另存成品。交付源码为 `db8e2ef3766a228bd2dd93f6e1e139b697d3ff18`。原工程与 210 及更早冻结记录保留，其他 12 项开发缺口见[剩余工作](../../remaining-work-211.md)。

## 实现行为

开始拍摄时先冻结已有 JPEG 的 handle 基线，避免下载整卡旧照片；采用原版策略，不为建立 20k 基线逐张读取元数据。ObjectAdded 事件只投递有界提示，串行工作线程通过周期盘点补足漏通知。新对象的元数据两次稳定后才授权下载，未写完、被删除、handle 复用及存储卡暂不可读分别处理。恢复后第一次可读的新卡作为该卡旧库存基线，不能把整卡旧图当新拍照片。

对象身份绑定相机身份、存储卡、handle 和完整元数据，下载收据再绑定 session、watch、对象 key、原名、字节与实际 SHA。项目层先保存接收意图，再幂等记录原图、冻结预设任务与完成收据；迟到响应、旧令牌和账号变化不能写入另一任务。相同源文件不会重复加入项目或生成重复版本。显式停止后不自动恢复；重新连接同一可信 GUID 的相机可以补未完成及断线期间的新对象。无法核对 GUID 时不跨连接自动合并。

默认预设可以选择“不使用”：仍收原图、加入项目，产生零效果任务，与原版行为一致。有预设时，候选入队时冻结设置，更改默认只影响之后的新候选。图像处理复用既有项目导出，保留照片当前编辑和原始文件。接收进度使用实际字节，校验、入相册及项目收据完成后才算完成；切换根标签保留生产者。

停止过程中，即使取消响应丢失，仍单独尝试持久停止；开始操作的迟到成功会按其准确 watch/token 补偿停止。连接仍开着却发生校验失败时暂停并提供“重新核对”，避免无限重下载坏对象。断线同步更新顶部状态，并提供“连接相机”入口。进度卡片保持相同宽度，小屏/大字体操作区可滚动。

## Android 实装与原生结果

最终 db8 安装专项 **56 项控件/状态检查、0 失败**，包含 18 个 widget 桥接场景；终端到达 teardown 并输出完整通过。新增 16 项覆盖自动收片、去重、可信/不可信重连、后台暂停发现、迟到下载/开始、取消响应丢失、校验失败停止重试、无默认及其切换、重连入口和 320px/1.6 倍字卡片。见 [安装结果](android/camera-db8e2ef-result.json)。

普通 x64 release 实际安装到 Android 12/API31 模拟器，从设备读回 APK 核对字节数和 SHA。使用自建 PTP/IP TCP 相机端，JPEG 为自制棋盘图，NEF 只有合成元数据，不是实体相机或真实传感器 RAW：

- 初始旧 JPEG 1、2 与 NEF 101 没有原片接收；三张新图各投递三次通知，均只完成一次接收。完成后再次投递重复事件也不重复下载。
- 6 号无事件且暂时 DeviceBusy，写完后由盘点补收；8、10 号在断线期间无事件新增，也均补收。
- 7、9 号各在 16KiB 后断流：每张两次尝试、一次完整完成，部分文件没有入库。旧记录和完成项没有重做。
- 共 9 个新原图（3–11），8 个唯一成品（3–10）；11 号在“不使用默认预设”时仅保存原图，无效果 task/version。逐个核对原图 SHA、JPEG 解码、索引唯一、项目/任务校验和、成品 manifest/JPEG 与不可变预设绑定，校验成品后再次读取原图，内容不变。
- [断线状态](android/final-disconnected.png)与[重新连接后](android/final-reconnected-complete.png)准确显示；大文件在切底部标签前为 [168KiB](android/final-before-tab-progress.png)，返回后为 [480KiB](android/final-after-tab-progress.png)，连接及进度持续。
- [停止后](android/final-stopped.png)加入 12 号，等待后仍为零次原片尝试。接收目录无 `.part` 遗留。

现有受控 210 项目含 1 个历史原图、任务及成品，未为测试删除。最终总数为 10 原图、9 任务，其中本轮 9/8。观察器按明确白名单核对历史行、原图 SHA 和旧成品；白名单在发现范围假设错误后识别，**不是独立的 211 前设备快照**。

4 次命令连接中，包含一次自动化过早返回造成的放弃初始化；原片各次完成数量单独核对，不能把连接数视为重复收片。

早期 `8117cf8dc234607fc6ee0a24d9bd5ef6858b8b4e` 普通包初收 3–6，并发现标题连接状态滞后、卡片宽度跳变；最终 db8 修正这些 UI 和重连入口。两者的共享核心、原生、应用状态、接收控制器、手动传输及项目处理生产代码相同。最终包实际恢复并核对旧完成项，收取 7–11；本记录不把 3–6 的首次接收写成最终包首次执行。实际范围和原片/成品数据见 [观察记录](android/final-release-scoped-v2-observation.json)。

## 范围和保留记录

A1 限应用前台、已验证协议范围的 Nikon JPEG。Fuji 自动拍摄明确禁用；后台服务、系统终止后的完整任务恢复、多选下载/保存目标、USB、遥控及 RAW 配对分别仍属其他缺口。前后台观察只是暂停/恢复发现，不等于系统保证后台运行。相机预览队列在自动收片期间暂停，停止后恢复；项目中可查看已收原图，该优先级仍需与原版交互逐项对照。

实体 Nikon/iPhone Wi-Fi、未知 NEF 高光、荣耀 Magic、真实账户及全部像素样式继续单独验收。合成 TCP 端、翻译后的核心和模拟器不能替代实体结果。

早期新 widget 夹具遗漏应用主题、Windows 宿主在加载前退出、观察器误把项目限定为只有新片、误把迁移索引限定为绝对路径，均保留为测试/观察器问题，没有计作通过，也未修改产品或删除历史数据来满足断言。最终观察器使用精确历史白名单，以及限定 `originals/<sha>.jpg` 或同一私有根绝对路径的校验后通过。

`dist/migration211/` 保留两个 APK、未签名 IPA、SHA256SUMS 和字节一致的证据副本。Android 签名、R8 RAW JNI 保留、字体/模型及 ELF/ZIP 16KiB 对齐已核对，IPA 需自行签名。早期包在 `candidates/`，不作为当前交付。另一任务的 212 修改在本轮本地冻结验证后才允许进入工作区，不混入本轮包；所有 211 结果固定到上述源码与记录。
