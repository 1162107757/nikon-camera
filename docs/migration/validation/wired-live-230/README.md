# USB 有线边拍边传

这是 229 之后的独立功能开发记录，不是 229 安装包的补充验收，也不代表新版已经发布。

## 用户操作

USB 连接尼康相机后，在同步页的拍摄接收中选择拍摄项目和 JPEG 或 RAW（NEF），明确点击开始。开始时记录相机中已有照片，只自动接收之后新拍的所选格式。原文件通过既有字节数、描述符和 SHA-256 收据校验后进入项目；项目默认预设生成的成品另行保存。

接收期间保持应用前台。停止会等待当前传输结束并停止发现新照片，相机连接仍可用于浏览和手动接收。拔线会暂停，重连后须核对原相机并明确继续；无法确认相机身份时开始新任务。相机机身必须允许在 USB 会话期间拍摄，兼容性需要真实机身、线材和转接器验证。

## 实现边界

- 复用原有只读照片会话、新照片基线、稳定元数据探测、格式选择、去重和原文件下载，不发送快门或机身写入命令。
- USB 没有可靠事件时，每 3 秒重新核对有界目录；收到事件只加入有界提示队列，不在系统回调中读取 PTP。
- 新增只用于自动发现的 canReadLiveObject 默认接口，其他客户端默认返回 true。iOS 要求同一会话的系统媒体目录包含对应 PTP handle，且文件大小与 PTP 元数据一致，再完成两次稳定采样。手动浏览和下载不受此接口限制。
- USB 的 cameraId/trustedCamera 复用已经存在的 downloadCameraId/downloadTrusted。有效的相机序列号支持同一相机的明确恢复；空、全零、unknown 等无效序列号保持会话隔离。更换相机或旧 watch/session 不得继续原任务。Wi-Fi 的 GUID 身份规则不变。
- 现有 Android NativeUsbCamera 和 UsbPhotoDirectory 的 229 目录修复不属于本次功能修改。其他聊天的 USB 槽位会话重用及照片传输适配器重写须单独提交、集成和验证。

## 验证记录

专项覆盖 JPEG/NEF 原文件和摘要、已有照片排除、缺失事件、未完成文件、系统目录延迟、相机忙、重复确认、错误格式、软停止、拔线、旧令牌及序列号恢复隔离。Flutter 用例覆盖两种格式、单次入库、停止保留连接及拔线后的明确恢复。

产品源码为 `770bc38`，只读接口批准记录为 `0150c48`，Apple 测试路径兼容调整为 `4544a35`。具体源码摘要和日志见 [local-checks.json](local-checks.json)。

- 隔离源码通过 JVM 1983 项共享边界检查及 6 项氛围检查，其中有线边拍边传专项 97 项；Flutter 拍摄接收 36 项通过，静态分析无问题。
- 229 的 Android MTP 适配器按 SDK 35 实编译，既有目录检查 124 项通过。这一结论仅对应本分支的原适配器。
- Apple 独立源码 `4544a35` 的 [CI 43730163848](https://github.com/1162107757/nikon-camera/actions/runs/43730163848) 通过。共享核心校验通过，修改后的 `HueviaWiredCameras.m` 有明确 CompileC 及构建成功记录，5 项 XCTest 无失败，原生照片管线收据成功并绑定同一源码。见 [Apple 收据](apple/receipt.json) 和 [编译证据](apple/wired-bridge-compile.log)。该模式没有生成 IPA，也不代表六项整合版 230 的 iOS 验收。
- 首次 Apple 尝试因缺少原始接口批准登记失败，已补齐精确 Git blob；之后用例路径工厂改为项目现有的 `Paths.get`。一次冷构建在新建模拟器的数据迁移阶段中断，记录保留；复用运行库缓存后的上述完整验证通过。备用任务在主任务通过后停止。

整合包的新适配器另外通过 41 项生产 USB wire 检查、2003 项共享边界及 6 项氛围检查，ARM64 release 的 RAW JNI/R8 检查通过。联合设备运行有 74 项通过及 1 项夹具启动时序失败，修复夹具后的聚焦重跑通过；没有将其写成整套联合测试全绿。完整范围以 [整合验收](../features-six-230/README.md)、`dist/migration230/ARTIFACTS.json` 和 263 项文件的 `SOURCE-INPUTS.json` 快照为准，不能借用本分支旧 MTP 适配器的编译结论替代整合验收。

没有发布公网更新，也没有真实相机通过记录。自动化使用模拟 USB/PTP 客户端；机身连线拍摄、线材及系统兼容性仍需接线实测。
