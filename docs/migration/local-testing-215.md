## 本轮重点

- 在照片编辑器点击「人像」，直接进入原安卓版样式的人像精修界面。
- 人像初始工具排为「皮肤 / 面部 / 塑形 / 自然精修 / 修补」；窄屏可横向滑动找到「修补」。局部选区模式仍按原行为隐藏不适用的工具。
- 修补单指涂抹；第二根手指落下时撤销当前未完成笔触，随后双指用于缩放、移动。必须全部抬起后才开始新的笔触。
- 拖动「画笔大小」时实时显示圆环，缩放时圆环与照片使用同一坐标和缩放比例。结束大小调节后圆环收起；预览和大小调节都不产生修补。
- 修补子页可逐笔撤销 / 重做。子页「应用」返回人像后，与进入前的人像效果一起保留，并合为一次父工作区撤销；子页「取消修补」保留进入前的效果。整个人像页还需点击「应用」才把结果带回照片编辑器，原图文件保留。

## 建议验收顺序

1. 准备测试照片副本；NEF 先显影。进入编辑器并点击「人像」，确认直接看到原式精修界面，原先的两个入口卡片不再出现。
2. 点击同排的「修补」，拖动画笔大小，确认圆环连续变大、变小；松开后圆环收起，照片不产生新修补。
3. 单指画一笔但不抬起，再加入第二指，执行双指放大、缩小、移动。确认整条未完成笔触被取消，照片没有产生这次修补；缩放移动期间不应新增修补。
4. 双指缩放后只抬起一指，用剩下的一指移动；也可在它未抬起时再放下一指。确认均不会补画或提交旧笔。全部手指抬起后，再以新的单指手势涂抹，应只提交这一条新笔触。
5. 放大并移动照片后拖动画笔大小，确认圆环仍对准照片；在明确的小目标上画一笔，再「适应照片」，核对修补落点没有漂移。拖动大小时触碰画布不应误提交；调节前的未完成笔触应取消。
6. 先调整肤色或人脸，再进入修补画两笔，试子页「撤销 / 重做」；点子页「应用」回人像，确认既有精修与修补都保留。此时父页撤销一次应回到进入修补前，重做恢复；另试子页「取消修补」，既有精修不得丢失。
7. 单指涂抹未完成时旋转屏幕，确认本笔取消；残留手指及其后加入的第二指仍不能把旧笔提交，全部抬起后的新笔才可编辑。
8. 试「适应照片」、撤销 / 重做、按住对比，以及修补处理中点击「取消修补」或系统返回。未完成笔触不应意外提交，取消后迟到的计算结果不得回写父人像。最后分别试整个人像的「应用」与取消，核对原图保留。

## 平台与验收边界

最终 x64 R8 包已在 API 31、4096 字节页模拟器实际运行 54 项通过，已安装 APK 的 SHA-256 与交付附件一致：[运行结果](validation/features-215/android/release-runtime-result.json)。实际安装后的 [屏幕检查](validation/features-215/android/release-ui.json) 确认人像直进、无中间入口卡、工具顺序一致；拖动大小时读数为 4.7%，结束后为 9.3%，圆环只在调节时显示。只调大小前后照片区域全部像素不变；单笔修补、撤销 / 重做、子页取消、父页取消均已操作核对，测试原图与外部副本摘要保持不变。该次检查没有应用或导出修补结果。

已实际完成的定向检查为初始指针 3 项、兄弟控件指针 4 项、画笔预览 15 项、直进入口 1 项和工作区保护 3 项，见 [本地结果](validation/features-215/flutter/local-results.json)。Windows 完整 25 项工作区测试因 `flutter_tester` 访问冲突未完成，不记为通过；随后同源 Mac 全量 350 项通过，原生综合场景与 PhotoKit XCTest 通过，见 [CI 结果](validation/features-215/apple/ci-result.json)。双指状态合同有真实指针测试，但实体设备多点触控尚未验收。**4 KiB 模拟器与 16 KiB 静态对齐不替代 16 KiB 实体设备验证。**

未签名 IPA 已通过 [独立核验](validation/features-215/apple/independent-verification.json)，由使用者自行签名安装。实际 iPhone 安装、自签能力和系统权限仍需实机检查。QQ Android 腾讯登记仍未核实保存生效；iOS Universal Link 尚未配置，真实 QQ 登录仍待平台配置与设备验证。

214 原四项需求与十一类功能继续保留，回归入口及条件见 [214 指南](local-testing-214.md)。实体相机、有线 / 无线连接、遥控和槽位支持、未知 NEF 及保存目标权限仍须分别实测，不能用本轮修补手势通过代替这些项目。
