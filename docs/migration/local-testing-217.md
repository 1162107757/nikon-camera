## 本次重点：QQ 登录免应用图片验证码

1. 「设置 → 顶部账号区域 → QQ 快捷登录」。本轮不再显示、请求或刷新应用图片验证码；同意授权说明后才调用手机 QQ 原生 SDK。未同意时不得开始授权。
2. 在 QQ 中取消后返回，应保持原账号状态，不显示登录成功。再试离开 QQ 登录页后才返回授权结果，旧结果也不应建立会话。
3. 正常授权后，必须由服务端完成腾讯身份校验并签发会话，才能更新账号状态。QQ/IP/安装及首次建号限流保留；第三方身份校验失败或服务限制应给出错误，不得直接当作登录成功。
4. **当前生产 QQ 接口已移除首次建号的额外图片验证码消费。** 已读回核对该唯一改动，普通注册仍要求验证码，无效 QQ 凭据仍被拒绝，见 [实际服务记录](qq217-server-review.md)。真实登录仍须手机 QQ、腾讯登记和有效授权；本轮未使用真实用户令牌验证成功登录。若连接到旧服务返回验证码要求，客户端保留「QQ 登录服务尚未更新，请稍后重试或使用账号密码登录。」提示，不退回图片验证码流程。
5. 在外部 QQ 授权中或服务交换期间切换账号，核对旧结果不会覆盖当前账号；离开页面后也不应被迟到回调重新登录。
6. 返回「注册账号」，核对原邮箱 / 账号密码注册验证码仍可加载、刷新、校验，注册成功仍可立即登录。此次移除仅针对 QQ 额外图片验证码。

QQ Android 新包名及签名的腾讯登记尚未实测确认；**iOS Universal Link 尚未配置**。手机 QQ、腾讯后台登记、域名 / AASA 与签名能力均是独立前提，自签 IPA 和本地回归不代替真实授权验收。详见 [217 QQ 差异与验证说明](qq-login-217.md)。

## 216 累积功能继续复测

准备有人像和小瑕疵的 JPEG 测试副本，以及已有裁切 / 旋转 / 塑形的副本；NEF / RAW 先显影再进入需解码照片的细节功能。

- 「人像 → 皮肤 → 自动祛痘」：有候选时照片上显示编号与范围，列表和照片定位相互对应；以「塑形前定位」图为准。逐项勾选、全选 / 全不选及数量同步，定位或缩放不直接应用效果。取消保留进入前状态；「修复所选」只应用所选项，并作为一次人像撤销。加载失败或账号失效时不能继续确认旧候选。
- 编辑器左上关闭旁的三点：核对原式锚定菜单、图标、分组、选中及条件禁用状态。继续试收藏、直方图、照片版本、查看细节、全部滤镜、快速优化、照片配方、精细构图、复制 / 撤销复制、条件继续编辑、重置调色、还原原图及删除入口。人像内原七项更多菜单独立保留。**删除仅用专门测试副本。**
- 直方图与暗部 / 高光警示只影响预览；全尺寸细节是只读临时查看，切换调色前 / 当前效果、100% / 200%、缩放平移及关闭不应新增版本、草稿或系统相册文件，关闭只返回编辑器一次。
- 「调节」继续核对 17 个参数的独立图标、数值和选中态：亮度、曝光、对比度、高光、阴影、白色、黑色、色温、色调、饱和度、自然饱和度、清晰度、锐化、明度降噪、彩色降噪、颗粒、暗角。另核对曲线、HSL、调色盘、去灰、局部、修补六个独立工具入口及大字 / 窄屏滚动。

候选照片、菜单和图标的详细操作见 [216 指南](local-testing-216.md)。该版的通过记录作为历史基线保留，不直接算作 217 安装包验收。

## 215 手势与完整编辑状态回归

点击「人像」直入原式工作区，工具顺序为「皮肤 / 面部 / 塑形 / 自然精修 / 修补」。修补子工具中，单指只绘当前笔；第二指到来立即取消整条未提交路径并转入双指缩放 / 平移。只剩一指时不能继续补画或提交，全部抬起后的新手势才能编辑。缩放后的落点、画笔圆环与照片必须保持同一坐标。

拖动大小滑条只改变候选大小与圆环预览，不应修改照片。分别试「照片先抬 / 滑条后抬」「滑条先抬 / 照片后抬」和照片先按、调节完成后照片才抬，均不得意外点按祛痘或提交修补。滑条结束后圆环收起。

子页确认应保留完整既有肤色、人脸、塑形及其他编辑，合为一次父撤销；子页取消恢复进入前状态，父页取消放弃本轮人像事务。整个人像仍需「应用」才成为编辑器结果。可结合 [215 建议验收顺序](local-testing-215.md#建议验收顺序)复测预览、撤销 / 重做和账号变化保护。

## iOS Z6II Wi-Fi 连接复测

**已确认用户使用 Nikon Z6II（“Z62”）与相机 Wi-Fi；本轮尚无实体 iPhone 连接成功的验收结论。** 用上述已核验 IPA 完成本机自签安装后，再按以下步骤复现；CI 通过不代替实体相机连接。

1. Z6II 进入「连接至智能设备 → Wi-Fi 连接 → 建立 Wi-Fi 连接」，iPhone 在系统 Wi-Fi 设置中连接机身显示的 SSID，再回 Huevia 核对 IP / 端口并连接。保持应用在前台，留意机身确认。这与旧 Android 引导一致，依据 [Nikon 官方智能设备连接说明](https://onlinemanual.nikonimglib.com/z7II_z6II/en/09_menu_guide_06_28.html)。
2. 首次先完成应用内说明，并在 iOS 本地网络弹窗允许访问；曾拒绝时通过页面的本地网络权限设置入口后重试。记录是否出现弹窗、是否允许，勿只记录「无响应」。
3. 核对页面显示具体阶段及已等秒数：Wi-Fi / 本地网络权限、机身确认、事件通道与会话、存储卡目录、照片目录与首屏读取。握手完成后的目录读取应有独立阶段及「取消读取」。
4. 握手与初始目录读取使用 75 秒核心总预算；首次应用内说明另有 45 秒上限，本地网络授权等待窗口最多 20 秒。页面还有 125 秒连接兜底，首屏读取单独 75 秒；这些是不同阶段的边界，并非每次必须等满。任一应用等待阶段都可取消并重试，旧结果不应接管新连接。
5. 若另试 USB，使用数据线和兼容转接器，经「检测 USB 相机」授权并选设备；授权等待上限 45 秒、检测页兜底 50 秒。拒绝、未发现设备、会话打不开或系统未提供 PTP 通道应明确报错，不能据 Wi-Fi 结果推断 USB 已通过。

「连接至电脑」是另一条含 Wireless Transmitter Utility 配对的流程，见 [Nikon 官方电脑 Wi-Fi 说明](https://onlinemanual.nikonimglib.com/z7II_z6II/en/10_establishing_wireless_connections_02.html)。目前不认定用户选错模式；请反馈现场实际入口及停留阶段。

若仍失败，请记录 **217 实际安装版本、iPhone / iOS、机身入口、SSID 是否已连、最后阶段与秒数、完整错误及本地网络授权情况**。握手完成但没有照片时，明确是「读取存储卡目录」还是「读取相机照片目录与首屏」，以区分连接与图库读取问题。
