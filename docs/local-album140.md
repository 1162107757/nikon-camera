# 相册来源与操作栏整理

0.28.3-beta（140），本地测试包。

相册标题右侧保留灰色横向更多图标。来源切换单独占一行，仅有“App 内”和“手机”。下一行左侧显示小字号“共 x 张”，右侧放轻量操作。移除整行“添加照片”按钮及悬浮加号，照片区域不再为悬浮按钮保留右侧空位。侧栏导航布局不预留底部导航高度；窄屏悬浮导航保留原有避让空间。

“App 内”用于浏览编辑与同步保存的照片，不常驻添加入口。空相册的“浏览手机照片”仅切换到手机页，不直接打开选择器或请求权限。“手机”保留“＋ 选照片”小按钮；有照片时显示“选择”，进入现有批量操作。更多菜单保留刷新、RAW 显影及相应权限管理，去掉重复的选择入口。

计数 12sp、操作 13sp、来源标签 14sp，沿用现有系统字体与 UiPalette。小操作的可见背景高 32dp，触摸目标至少 48 × 48dp，操作间距 8dp。来源轨道高 48dp，外圆角 24dp，选中背景四周等距 4dp、内圆角 20dp。操作文字与计数使用同一灰色。部分授权在来源标签中显示“手机 · 部分”，避免多加一排权限解释。

手机相册查询、JPEG/PNG 多选、原图保护、工作副本、批量编辑/保存、RAW 显影与已有编辑流程沿用原实现。此次没有改动图片处理与相机连接逻辑。

验证采用生产原生 View 与自有 JPEG/MediaStore 测试照片，覆盖手机、1.3 倍字体、深色、扩展平板视口、横屏、未授权及部分授权；最终报告见 `docs/validation/local-album140/final/`。选图启动由系统框架分发后返回取消。外部系统选择器的界面与实体手机/平板效果未验收。

初次预检的测试照片放在目录边界之外，被真实目录校验排除，造成测试等待超时。随后仅修正测试数据位置，并用不同 JPEG 字节避免照片分组合并；生产代码未因此修改。最终证据以 `final/` 为准，初始记录在 `native/phone/`。

现有 OrangeNativeProbe 的相册断言同步适配新控件名称、手机专属选图及标题栏更多入口；该大型探针不计入本次原生运行结果。

首次独立审阅指出横屏空相册仍保留侧栏布局不需要的底部空间，导致引导按钮被裁切。已针对导航占用修正，并补充空相册完整按钮可见性的原生断言。

修正后七个配置均通过，共 238 次断言执行（不是 238 个独立场景）。复审将唯一发现评为 resolved，结论为 SHIP，范围仅覆盖该修复及其直接横屏网格回归检查。最终 APK SHA-256：`bd0a25e10c6134897828666b8b1e83193c3e039a984b88e7bd48fa8f606063d7`；已核对模拟器安装包一致。
