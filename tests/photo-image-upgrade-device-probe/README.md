# Native photo editor / detail probe

Standalone framework instrumentation uses the installed candidate's real `MainActivity`, local photo workspace, five editor tools, detail viewer and histogram. It never clears app data, installs a production APK, or operates a physical device.

Build once, then use the reserved **emulator-5586** only after the root agent installs the agreed immutable candidate:

```powershell
powershell -ExecutionPolicy Bypass -File tests/photo-image-upgrade-device-probe/build.ps1
powershell -ExecutionPolicy Bypass -File tests/photo-image-upgrade-device-probe/run.ps1 -Mode phone -CandidateApk D:/absolute/candidate.apk -PresetFixture D:/dev/ai-project/nikon/.tooling/bluesky-preview/Bluesky.NCP
```

The default `-Scope polish` verifies version 93's editor/detail text and alignment. Run **phone → font1.3 → landscape** serially after the root agent supplies the candidate and device authorization. Unchanged backend/export/progress/dark suites are not repeated. The runner reads the candidate version, checks the installed APK's exact SHA, pins probe inputs and restores font, night, rotation and permission settings. Evidence goes to `docs/validation/photo-polish-93/<mode>/`; the device output also includes candidate SHA and unique run ID to avoid mixing attempts. Version 92 requires explicit `-Scope prototype` and retains `docs/validation/photo-prototype-92/` with its original candidate identities.

Version 94 uses explicit **`-Scope load`**, limited to **phone → font1.3**, and writes `docs/validation/photo-detail-load-94/<mode>/`. It covers the real album label “边拍边传”, a detail entry that opens while `editor.io` is blocked, first-frame loading with no dimension placeholder, actual provisional/full frames, pending/ready 100% and 200% certification, real cache-storage failure and retry, close guards and the existing decoded-JPEG/framebuffer pixel oracle. Its 4320×2880 photograph and non-neutral draft are private fixtures. A test-only profile proxy gates full-width processing and delegates every production pixel operation unchanged, retaining the geometry/border wrappers; it never manufactures frames. These scheduling holds make raw intermediate screenshots deterministic and **are not performance measurements**. A normal file at the fresh Source's own UUID cache-directory path triggers the actual storage failure; removing only that file allows the real retry. The original JPEG is never modified. Existing versions' reports keep their original candidate identities, and no five-tool/export/backend/dark suite is repeated by this scope.

The entry check calls the actual Button listener with `performClick`; it does not independently claim touch hit testing. Its close case dismisses before the first queued frame runs and verifies cancellation/cache release, rather than claiming coverage of an already-running renderer's delayed callback. Status evidence requires every line to fit without ellipsis and the last layout line to reach the full string end. Cleanup accumulates errors while continuing other source releases, own-file deletion and all restorations before reporting failure.

`-PresetFixture` is optional. It supplies actual NCP bytes and SHA to the production parser and only the probe's unique JPEG draft. It does not add to the user's preset library. The approved Bluesky file exercises no-change strength with a real selected filter. Missing or invalid presets produce an explicit **SKIP** with a reason; the probe never fabricates a profile.

The prototype scope checks:

- True 100% with a unique 2401×1601 high-frequency JPEG. Full-resolution tiles and over 500 raw framebuffer pixels are compared with the actual JPEG decoder output; `pixel-mapping.json` contains source/screen coordinates.
- Fit / 1× / 2×, minimap navigation, same-position current/before comparison, unframed editing content, and whole saved JPEG pixels including baked borders. Saved versions show an explicit unavailable-before reason.
- Two-line real filename header, 26dp metric inside a real 48dp action, and actual pointer input outside the visual tag that opens its information dialog. In the polish scope the footer is absent and complete saved/physical-pixel explanations remain in accessibility and the information dialog.
- Actual glass and selected Drawable bounds, equal edge gaps, inner radius derived from outer radius minus gap, medium text size, real selected fill pixels and the raised locator. These checks measure native geometry and framebuffer pixels, not just selection flags.
- Five real tool tabs retain photo bounds, pixels and edit identity. Real filter-grid search, precise value validation and undo, composition summary/workspace, cancel without mutation, apply as one undo step, border settings and recipe naming/cancel. Landscape crop upper corners receive actual screen-coordinate pointer drags.
- Unchanged strength preserves edit flags, undo, preview requests and the own draft's bytes and modified time.
- Histogram mode-line pixels, custom chip glyph bounds, actual 8dp striped swatches, 4dp gap, centered swatch/text group, minimum padding, 28dp face and 48dp target. Native pixels prove the patterns and selected text are painted. RGB/warnings retain photo/dock stability and do not alter effect pixels, draft identity, source bytes or the private comparison render. A gated preview worker checks that closing the histogram cannot drop the final edit.
- Five tool text layouts, centered header, fully visible 48dp compare action, GRID zero-result count and short empty text, compact composition actions, rotation without offset icon, and real parameter/strength/recipe/border dialogs. Typography JSON and unedited screenshots retain each dialog's actual sizes and baselines. Input alignment JSON compares text origins including native compound padding and scroll, verifies the real 20dp form inset, and allows up to 8dp for platform title/body insets.
- Same-photo rebind and owner invalidation close the real detail source. Unique JPEG/draft fixtures are deleted in `finally`, recording integrity and absence. Appearance preferences are restored.

Captures are unedited native PNGs; hero files are byte-identical copies of the raw captures. The photograph comes from shipping `res/drawable-nodpi/preset_template.png`, scaled only as a fixture, without claiming recovered optical detail. No camera, physical-phone or MediaStore validation is claimed.

The historical version 91 suite requires explicit `-Scope image-upgrade`. It includes unchanged export-input validation and writes `docs/validation/photo-image-upgrade-91/<mode>/`. Its real APP_ONLY batch/progress path requires both `-Scope image-upgrade -ProgressOnly`, writing `<mode>-progress/`. Neither historical path is rerun for version 92. Earlier reports retain their original candidate identities and scope.

For the final saved-version reason text style alone, use `-Scope prototype -Mode landscape -SavedReasonOnly` with the exact new candidate and the same real `-PresetFixture`. This recreates the existing baked-JPEG fallback fixture and checks the saved reason, whole-file dimensions, disabled-before state and immediate entry/window guards. Its raw screenshot and report go to the separate `landscape-saved-reason/` directory. It does not rerun or relabel the three-configuration matrix; legibility on bright architecture/skin still requires looking at the native screenshot.
