# 135 紧凑布局原生验证

复用 direct-tools133 的 Android API-only 反射测试脚手架与独有离线夹具，包 cc.huevia.compactlayoutqa。只从已安装且 SHA 匹配的生产 APK 取实现。入口为 layoutAssertions 后 compactFlow；未调用的旧方法不算本轮断言。

在任务拥有的模拟器预装本轮候选，先运行 build.ps1，再向 run.ps1 传 CandidateApk、ExpectedApkSha256、Mode、Scope、Serial。phone 使用 full，其余模式 ui。平板由外层设置为 1600×2560 / density 240 并恢复。禁止对实体用户手机运行夹具脚本。

新增检查：顶部四个可见区域、动作顺序、序号居中、48dp 触摸范围、横向更多图标、保存图标、模拟 quickBusy 状态的标签/图标恢复与不截断。测试只注入状态检查显示，不冒充一次真实优化任务；后续 compactFlow 会运行真实快捷分析。

检查参数四个控件共处 48dp 行、滑杆宽度和完整边界、148dp 面板与整体尺寸、滤镜 176dp 与缩略图完整、四项人像与四个快捷卡可见。通过 Android 窗口真实点击新位置的 More/Save，确认打开菜单与既有保存面板；继续验证 17 个直接参数、精细工具、横滑、撤销、局部范围、人像、草稿与导出流程。

保存按钮现在为低填充表面，因此截图绘制检查遍历按钮区域的桃色前景像素，取代只对旧大色块采样的断言。不会跳过按钮绘制或边界检查。四种模式使用同一候选；完整流程仍核对冻结草稿和实际生产渲染，不声称实体设备性能或 MediaStore 发布。

第二轮额外检查横屏工具容器按内容高度排列，避免 fillViewport 把背景撑出空白色带。
