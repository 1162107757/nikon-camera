# Portrait model and pipeline host regressions

Run `./tests/portrait-host/run.ps1` with JDK 17. This compiles production `ncp` classes and the real draft, recipe and adjustment-copy stores, then runs nine small dedicated entrypoints. It does not require Android, a camera, network access or a face photograph.

`PortraitModelTest` checks immutable state, canonical serialization/identity, zero-effect and disabled faces, bounded face/heal/stroke/point counts, invalid values, unknown wire versions, strict boolean values and every truncation of a representative serialized portrait.

`PortraitLandmarksTest` uses a synthetic 468-point local mesh to check defensive copies, indexed access, finite coordinate bounds, signed-zero canonicalization, all face copy methods, optional per-face encoding and malformed/truncated mesh payloads. Its independent frozen version1 writer verifies that legacy geometry, settings, skin samples, strokes and heals survive migration without invented landmarks. Nested `PhotoLocalEdits` and owner-scoped persistent drafts retain the complete mesh and keep stale-export/compare-and-replace guards. It checks storage contracts, not landmark inference or photographic mask quality.

`PortraitSkinMaskTest` checks the independent optional 128×128 semantic-confidence raster. Analytic ramps and four explicit pixel values verify unsigned bytes, pixel-centre bilinear interpolation and clamped border sampling; invalid bounds, immutable data, all mesh/mask presence combinations, legacy version1, malformed/truncated payloads, nested local edits and draft-owner/export guards are checked separately. Mesh and semantic mask may each exist without the other. Legacy version2 stores optional mesh followed by optional semantic bounds and bytes; version3 retains those fields before its per-person tone and body-skin payloads. Version4 keeps the complete per-person layout and appends global tone and confidence after the heal list.

`PortraitLandmarkMaskTest` uses a synthetic expanded outline and intentionally relocated eye/brow/lip contours. Independent point and pixel oracles check forehead/cheek coverage, feature protection, background exclusion, manual override order, full-render bounds, non-square images, roll, eight EXIF orientations, disabled-face selection and actual-contour under-eye correction. It does not copy the production polygon raster or certify photographic segmentation quality.

`PortraitSemanticMaskTest` supplies independent synthetic face-skin probabilities with a forehead extending above the mesh and an occluding-hand hole inside it. It checks that semantic probabilities own coverage without a second ellipse/top/chroma clipping pass, while real feature contours still protect eyes/brows/lips/nostrils. Full-image brightness oracles catch truncated processing bounds, and strokes, soft confidence, non-square/rolled frames, disabled selection, all EXIF directions and absent-semantic legacy paths are verified. These tests exercise the production processing branch; they do not execute or validate semantic-model inference on photographs.

`PortraitPipelineTest` uses deterministic synthetic images to check independent face adjustments; light and dark sampled skin; unchanged background/eye pixels; add/erase/re-add strokes; smoothing versus texture retention; target-colour healing; unchanged alpha; zero-effect pixel identity and zero pixel I/O; cancellation/interruption and injected I/O errors. All eight EXIF directions are compared against an independent integer-oriented pixel reference, including combined smoothing, light and healing. These fixtures are representative algorithm cases, not a demographic or photographic-quality benchmark.

The same entrypoint verifies byte-for-byte old local-v1 serialization and identity, existing PED6/local-v1 draft loading, portrait/local-v2 roundtrip, frozen draft/profile/export identity, owner isolation, stale-export and copy/undo conflicts (including zero-effect face selections), target portrait preservation during global adjustment copy, and exclusion of photo-specific portrait coordinates from reusable colour recipes. Temporary persistence fixtures are removed from their own newly created OS temporary directory.

`PortraitToneTest` checks the original plus nine immutable catalogue entries, custom 24-bit targets, independent per-person strength and scope, every face copy method, immutable full-image body confidence and its analytic bilinear sampling. Independent frozen v1/v2 writers verify migration to neutral tone, while mixed v3 faces, malformed payloads, nested local edits and real owner-scoped drafts verify persistence and stale-export protection. The complete maximum draft combines twelve meshes and two confidence rasters per face, 64 portrait strokes/8192 points, 64 heals, sixteen 512-point local brushes and 64 clones, and verifies actual save/read plus headroom under the two-MiB draft cap.

Tone pixel oracles require exact no-op output for original, zero strength, disabled people and a target matching sampled skin. All nine presets retain shadow/highlight order, fine lightness texture and alpha at maximum strength. Extreme custom targets keep contrast, with perceptual hue observed through an independent sRGB→XYZ→Oklab conversion. Face/body scope, protected features, background exclusion, manual overrides, bounded full-image rendering, cancellation, progress, independent people, non-square frames, roll and eight EXIF orientations are checked without copying the adaptation implementation. These checks do not certify photographic colour quality or body segmentation.

`PortraitGlobalToneTest` starts from `PhotoPortrait.NONE` with an empty face list. Disconnected synthetic face/neck/arm/leg skin islands receive colour while every zero-confidence background pixel remains exact. Original, zero strength, pending/empty masks and transparent source pixels are handled independently. Changing unrelated background colours or stored face RGB samples cannot bias the mask-weighted source reference; a custom target matching uniform source skin is bit-exact. Optional real meshes protect features without imposing a face envelope, and old manual face boxes cannot punch assumed features into whole-image body skin.

Independent v1/v2/v3 encoders verify that published per-person drafts migrate with neutral global state. Version4 global-only serialization, complete face/heal copy methods, mutually exclusive global/person modes, malformed payloads, owner-scoped persistence, stale exports and maximum nested draft sizes are checked. Real draft/profile/export wrappers render global colour even with no faces. Odd non-square images larger than the 256×256 reference sample grid are compared under all eight EXIF mappings, including partial alpha, bounded source-row reads and optional rolled meshes. Cancellation, progress and read failures cover both reference sampling and the full-image render. These tests do not execute semantic inference or claim photographic segmentation quality.

`SkinBodyRegionsTest` checks the separate multi-source ownership utility with synthetic categorical grids, including disconnected people, foreground connectivity, competing face seeds, exclusion of background, unseeded components, category/seed validation and cancellation. It does not execute the Android segmentation helper or certify instance ownership for overlapping people.

Compile/runtime output is saved by the calling agent in `.build/`; the script reports failures through its process exit code. The native Android detector, dialog, codec and full-render integration are checked separately by `../portrait-device-probe`.
