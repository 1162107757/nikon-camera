# Photo tools 109 native probe

Standalone reflection-only instrumentation, compiled against Android API35 alone. It does not compile or package production classes, install the candidate app, clear its data, publish to MediaStore, or touch a camera. Root installs the exact frozen candidate on an exclusively owned emulator, then runs this probe.

Build with `build.ps1`. Run `run.ps1 -CandidateApk <absolute APK> -ExpectedApkSha256 <SHA-256> -Serial emulator-5586 -Mode phone`. `font1.3` and `landscape` reuse the same probe for the initial bounded layout pass. The runner verifies installed APK bytes and actual version, source/probe provenance and emulator hardware, temporarily sets font and airplane mode, then restores them and removes only its instrumentation package. Evidence stays in fresh folders under `docs/validation/photo-tools-109/`.

Native menu selection first acknowledges the exact `com.android.systemui` / `Got it` immersive-mode teaching prompt when present, using its real accessibility click. It then searches the app's active/interactive windows and clicks the real menu item or its clickable parent. The runner saves and restores `immersive_mode_confirmations`; app geometry/menu callbacks are never invoked as a workaround. Pinch input also reads the device's actual minimum scaling span and slop instead of assuming a small fixed pixel distance.

Cleanup restores each setting and uninstalls instrumentation independently. Empty/whitespace/`null` settings restore their default via delete, cleanup errors are recorded in `cleanup.json`, and an original instrumentation failure remains the primary thrown error. A setting failure cannot prevent the instrumentation uninstall.

The probe drives real MainActivity / AlbumPanel / PhotoFilterEditor with two owned private JPEGs (one EXIF6): local radial/brush/gradient and explicit-source clone gestures, two-finger navigation without extra strokes, cancel/apply/history/draft switching, new global detail controls, actual native perspective menu choices, owner mismatch rejection, and close-resource guards. Private full-resolution PNG reference and real-detail render paths are compared pixel for pixel, including an independent integer EXIF6 orientation plus actual profile render oracle. The real detail dialog's sample-1 tiles are sampled against the full reference, then its worker and temporary surface must close. Source SHA must stay unchanged. Six successful screenshots per mode cover the new controls.

Full/Q95 exports may retain raw storage direction plus JPEG EXIF to preserve existing artifact identity. The PNG encoded immediately before that JPEG has the same storage direction, so the probe reads the **actual exported JPEG's EXIF** and performs a lossless integer permutation of the reference before comparing it with the oriented detail surface. The pixel threshold remains zero.

Owner invalidation is simulated by changing the editor's private scope field and immediately restoring it; this is not a real account transition or authentication certification. This probe also does not certify a physical phone, RAW decoder support, camera connectivity, or the separate actual-export-preview dialog. Generated source/render/draft fixtures are removed individually in instrumentation cleanup; shared app data and prior evidence remain.
