# 136 菜单与滑杆端点原生验证

从 134 复用 Android API-only 脚手架、候选 SHA 核对和独有离线夹具，入口为 menuSliderFlow。包 cc.huevia.photomenuqa，生产类仅从实际安装的 APK 反射取得。旧未调用辅助方法不计断言。

在任务拥有的模拟器预装候选，运行 build.ps1 后给 run.ps1 传 CandidateApk / ExpectedApkSha256 / Mode / Scope ui / Serial。模式包括 phone、font1.3、font2.0、landscape、tablet；平板由外层设定并恢复 1600×2560 / density 240。禁止用于实体用户手机。

检查短标题、说明、图标、48dp 触摸区域、可达性和屏幕边界。真实窗口注入点击直方图、重置、还原和复制动作；验证状态、当前调色、保留人像及撤销恢复。复制/撤销复制拦截现有 Host 委托，不实际更改其他照片。源切换通过同一 UI 回合临时改变本测试引用，检查过期动作被抑制；重绘检查旧浮层关闭。

真实拖动主调节、优化、人像快捷滑杆至两端，检查 progress 和生产参数为准确最小/最大值。按住时检查完整原生 thumb 边界均在 View 内并截图。滤镜未选择夹具预设，因此只设置显示进度检查其两端几何，不冒充一轮滤镜效果渲染。

初轮测试使用 getGlobalVisibleRect 的窗口内坐标注入弹窗触点，之后改为 getLocationOnScreen 的屏幕坐标。横屏也需将浮层高度限制为实际安全显示区域，不能只信平台返回值。完整断言保留。

第二轮横屏遇到测试辅助方法的 fling(0) 覆盖紧随其后的 scrollTo，其他四种模式已通过。去掉该零速 fling 后，在同一生产 APK 上补充横屏确认，81 项检查均通过。各次运行保留独立的探针源码、APK 和 SHA；失败记录不计入最终 405 次断言与 30 张截图。
